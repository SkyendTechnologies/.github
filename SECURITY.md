# Security Policy

Skyend Technologies takes security issues seriously.

## Reporting a vulnerability

**Do not open a public issue for an unpatched vulnerability.**

Use the repository's private vulnerability reporting feature when it is available. If the repository does not provide a private reporting channel, contact Skyend Technologies through:

https://t.me/SkyendTechnologies

Please include enough information to reproduce and assess the issue:

- affected repository and component;
- affected version, branch, or commit when known;
- vulnerability description and potential impact;
- reproduction steps or proof of concept;
- relevant logs or traces with secrets removed;
- suggested mitigation, if you have one.

## Scope

Security support and release status are repository-specific. A repository's own security documentation takes precedence over this organization-wide policy.

Research prototypes, archived repositories, and experimental branches may not receive the same support guarantees as actively maintained software.

## Disclosure

Please allow maintainers a reasonable opportunity to investigate and address a report before public disclosure.

Never send production credentials, private keys, access tokens, personal data, or other secrets as part of a report.
