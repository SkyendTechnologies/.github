# Contributing

Thank you for your interest in contributing to Skyend Technologies.

This document provides organization-wide defaults. Repository-specific contribution instructions always take precedence.

## Before you start

- Read the repository README and documentation.
- Check existing issues and pull requests before opening a new one.
- Keep changes focused on a single problem or improvement.
- Avoid unrelated refactors in the same pull request.
- Do not include secrets, credentials, private data, or generated artifacts that do not belong in source control.

## Changes

Prefer small, reviewable commits with clear messages.

When behavior changes:

- add or update tests where practical;
- document important architectural or operational changes;
- include migration notes when compatibility is affected;
- verify formatting, linting, type checks, and relevant test suites.

## Pull requests

A pull request should explain:

1. what changed;
2. why the change is needed;
3. how it was verified;
4. any known limitations, compatibility concerns, or follow-up work.

Draft pull requests are welcome for work in progress when early technical feedback is useful.

## Security

Do not report security vulnerabilities in public issues.

Follow the repository security policy or the organization-wide [SECURITY.md](./SECURITY.md).
